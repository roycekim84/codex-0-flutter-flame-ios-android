# 전투 화면 완성도 고도화 로드맵

## 현재 판단

현재 전투 화면은 `BattleState → BattleEngine → Flame renderer` 구조와 턴 진행, 부대 선택, 이동, 공격, AI 턴, 결과 연결까지 구현되어 있다.

하지만 참고 화면과 비교하면 현재는 “플레이 가능한 전투 프로토타입” 단계다. 목표는 390×844 세로 화면에서 다음 네 가지가 동시에 느껴지는 고전 전술 전투 화면이다.

- 전장과 부대가 한눈에 읽힌다.
- 아군·적군·병종·부대 규모가 즉시 구분된다.
- 한 번의 행동이 화면에서 납득되게 보인다.
- HUD와 명령 버튼이 게임 화면의 일부처럼 통일되어 있다.

## 단계별 로드맵

### P0 — 기준 화면과 레이어 계약 고정

상태: 부분 완료

목표: 이후 에셋과 UI를 수정해도 배경, 격자, 부대, 효과, HUD가 서로 침범하지 않도록 한다.

- 전투 논리 좌표를 390×844 기준으로 유지
- Flutter HUD와 Flame 전술판의 영역을 명확히 분리
- 순수 지형 배경과 Flame 오버레이를 별도 에셋으로 유지
- 모든 부대 이미지의 실제 알파 채널 검사
- 작은 iPhone과 Android 세로 화면에서 오버플로 검사

완료 기준: 배경에 성·문자·부대가 중복으로 나타나지 않고, 화면 크기가 달라도 전술판이 잘리지 않는다.

### P1 — 전장 배경과 Hex Grid 고도화

상태: 진행 중

목표: 참고 화면처럼 전장이 넓고 풍부하게 보이며, 격자가 지형 위에 자연스럽게 얹힌다.

- 평원·숲·산·강·다리의 시각 대비 조정
- 중앙 플레이 공간은 밝고 가장자리는 약간 어둡게 처리
- Hex 선의 불투명도와 두께를 낮춰 부대를 가리지 않게 조정
- 선택 칸, 이동 가능 칸, 공격 가능 칸의 색상 체계 통일
- 강·산 위에 부대가 배치되지 않도록 지형 점유 규칙 연결
- 카메라 확대·이동은 후순위로 두고 한 화면 전장 완성 우선

완료 기준: 격자와 지형이 동시에 보이고, 부대가 배경에 묻히지 않는다.

### P2 — 병종별 부대 스프라이트 완성

상태: 부분 완료

목표: 보병·기병·궁병이 작은 화면에서도 실루엣만으로 구분된다.

- 보병·기병·궁병·창병 4종 제작
- 각 병종의 아군·적군 색상 변형 제작
- 모든 PNG는 투명 배경으로 검증
- 부대 규모에 따른 small·medium·large 변형 적용
- 스프라이트의 발밑에 불필요한 그림자나 사각 배경 금지
- 동일 이미지 디코딩을 피하고 Flame 이미지 캐시 사용

완료 기준: 전투 화면에서 최소 4병종과 2진영이 명확히 구분된다.

### P3 — 장수 표식과 부대 정보 패널 개선

목표: 참고 화면처럼 부대의 주체와 병력 규모를 즉시 읽을 수 있게 한다.

- 장수 이름 깃발을 부대 스프라이트와 분리
- 아군·적군별 깃발 색상과 테두리 차등 적용
- 선택 부대는 깃발·외곽선·하단 패널을 함께 강조
- 병력 숫자 패널에 천 단위 구분과 가독성 높은 외곽선 적용
- 부대가 작을 때 이름과 숫자가 겹치지 않는 배치 규칙 추가
- 선택된 적 부대에 예상 피해와 공격 가능 여부 표시

완료 기준: 부대 선택 없이도 이름, 진영, 병력 수를 쉽게 식별할 수 있다.

### P4 — 전투 HUD와 프레임을 게임 화면화

목표: 현재의 일반적인 Flutter 패널을 참고 화면 수준의 고전 전략 UI로 통일한다.

- 상단 공격군·방어군 패널에 금속 프레임과 진영색 적용
- 전투 일수 패널을 중앙에 고정
- 군량·사기·보급 부족 상태를 상단 또는 하단 정보 영역에 통합
- 명령 버튼에 정상·선택·비활성·잠금 상태 추가
- 하단 명령 버튼의 아이콘·라벨·간격을 통일
- 전황 정보 패널을 장식 프레임과 분리된 읽기 영역으로 정리
- SafeArea와 하단 한 손 조작 영역 보장

완료 기준: HUD가 배경과 따로 노는 Flutter 위젯처럼 보이지 않고 전투 화면의 일부처럼 보인다.

### P5 — 행동 연출과 전투 피드백 강화

목표: 공격 버튼을 누른 결과가 숫자 변화만이 아니라 화면 행동으로 느껴지게 한다.

- 일반 공격: 공격 방향선, 짧은 충돌 플래시, 피해 숫자
- 돌격: 부대 이동 잔상, 충돌 확대, 반격 피해
- 협공: 참여 부대 연결선과 동시 피해 숫자
- 화공: 불길, 연기, 화재 타일, 사기 감소 표시
- 정보: 대상 정보 패널과 잠금 해제 연출
- 피해 숫자에 아군·적군·치명적 피해별 색상 적용
- 애니메이션 중 중복 입력 차단
- 연출 완료 후에만 다음 행동 허용

완료 기준: 행동마다 시각적 차이가 있고, 피해량과 상태 변화의 원인을 이해할 수 있다.

### P6 — 전투 로그와 결과 흐름 보강

목표: 11번 대기 화면에서 12번 행동 연출, 13번 결과, 14번 포로 처리까지 흐름을 완성한다.

- 최근 전투 로그 3~5건을 하단에 표시
- 공격자·대상·행동·피해·사기 변화를 사람이 읽을 수 있게 기록
- 전투 종료 시 승리·패배·퇴각 원인을 표시
- 남은 병력, 포로, 전리품, 점령 지역을 결과에 연결
- 포로 처리 화면에서 등용·석방·처형 결과를 GameEngine에 반영
- 전투 로그와 월간 게임 로그의 용어 통일

완료 기준: 전투 시작부터 결과와 포로 처리까지 사용자가 다음 행동을 잃지 않는다.

### P7 — 반응형·성능·접근성 QA

목표: 고품질 화면이 특정 브라우저 크기에서만 유지되지 않도록 한다.

- 390×844 기준 Web 테스트
- 작은 iPhone, Pro Max, 일반 Android 세로 테스트
- 텍스트 스케일 증가 시 HUD 겹침 검사
- Web에서 큰 PNG의 초기 로딩 시간 측정
- 이미지 캐시와 Flame 컴포넌트 재생성 비용 점검
- 전투 중 60fps 목표 확인
- 터치 영역 최소 크기와 명령 버튼 연타 방지 확인

완료 기준: 주요 세로 화면에서 잘림·겹침·흰 배경·입력 중복이 없다.

### P8 — 최종 회귀와 콘텐츠 교체 준비

목표: 전투 화면을 generic engine의 안정된 기능으로 고정한다.

- BattleEngine 순수 Dart 테스트 보강
- 시드 기반 동일 전투 재현
- AI와 플레이어가 동일한 BattleCommand 경로 사용
- 배경·부대·HUD 에셋 교체만으로 시나리오 분위기 변경 가능 확인
- 11·12·13·14번 화면 회귀 테스트
- Web release build와 모바일 release build 확인
- 전투 화면 구현 문서와 에셋 목록 업데이트

완료 기준: 전투 로직을 수정하지 않고 새로운 세계관 데이터와 에셋을 적용할 수 있다.

## 우선순위

1. P1 전장과 격자
2. P2 병종 스프라이트
3. P3 장수 표식과 정보 패널
4. P4 HUD와 프레임
5. P5 행동 연출
6. P6 결과·포로 흐름
7. P7 반응형·성능 QA
8. P8 최종 회귀

## 현재 완료 상태

- 턴제 아군·적군 진행
- BattleEngine 기반 행동 처리
- 순수 지형 전투 배경
- 보병·기병·궁병 스프라이트 연결
- 투명 PNG 알파 채널 검증
- 부대 선택·이동·공격 가능 칸 표시
- 전투 결과·포로 처리 연결
- 39개 순수 Dart 테스트
- Flutter Web release build

다음 작업은 P2의 창병 스프라이트 추가가 아니라, 이미 추가된 병종들이 실제 화면에서 충분히 구분되는지 검토한 후 P3의 장수 표식과 병력 패널을 고도화하는 것으로 진행한다.
