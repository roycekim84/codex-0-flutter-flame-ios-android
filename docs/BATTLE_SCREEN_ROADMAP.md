# 11·12번 전투 화면 구현 로드맵

## 목표

11번 전투 대기 화면과 12번 전투 행동 연출 화면을, 참고 이미지와 같은 정보 밀도와 조작 흐름을 가진 세로형 전술 화면으로 완성한다.

원작의 그래픽·초상화·문구를 복제하지 않는다. 새로 생성한 지도·부대·장수·이펙트 에셋과 독자적인 색상·프레임·문구를 사용한다.

완료 기준은 “전투 화면이 뜬다”가 아니다.

- 390×844 세로 화면에서 HUD와 전술판이 모두 읽힌다.
- 전투 상태와 렌더링 상태가 분리된다.
- 선택 부대, 이동 가능 칸, 공격 대상이 즉시 구분된다.
- 이동·공격·화공·돌격·협공·정보·대기·퇴각의 결과가 같은 BattleEngine에서 계산된다.
- 행동 결과가 피해 숫자, 사기, 화재, 전투 로그, BattleResult로 연결된다.
- AI 전투도 동일한 BattleState를 사용하며 전투 UI에 치팅 데이터가 들어가지 않는다.

## 참고 화면에서 재현해야 할 구조

### 11번: 전투 기본 화면

1. 장식 프레임과 화면 제목
2. 상단 좌측 공격군, 중앙 전투 일수, 우측 방어군 HUD
3. 육각 격자 전술 지도
4. 강·산·숲·평원·성의 지형 표현
5. 진영별 부대 색상과 장수 이름 표식
6. 부대별 병력 숫자
7. 선택 부대 강조와 이동·공격 가능 범위
8. 하단 명령 바: 이동, 공격, 책략, 정보, 대기, 퇴각
9. 하단 전황 정보: 지형, 날씨, 효과, 보급 상태

### 12번: 전투 행동 연출 화면

1. 11번과 동일한 상단 전투 HUD
2. 행동 직전 선택 부대와 대상 부대 강조
3. 화공·돌격·협공별 전용 연출
4. 피해 숫자와 사기 변화 표시
5. 불·연기·충돌·피격 파티클
6. 장수 이름 표식과 진영 색상 유지
7. 하단 전투 로그 패널
8. 행동 완료 후 다음 명령을 받을 수 있는 상태 전환

## 구현 단계

### B0 — 전투 화면 계약 고정

- [ ] `BattleState`에 선택 부대, 선택 대상, 이동 가능 칸, 공격 가능 칸을 표현할 읽기 모델 추가
- [ ] `BattleCommand`를 이동·공격·화공·돌격·협공·정보·대기·퇴각으로 명확히 분리
- [ ] `BattleResultEvent`에 공격자·피격자·피해·사기 변화·화재·로그 문구를 포함
- [ ] Flame Component가 수치를 계산하지 않도록 검증 테스트 작성
- [ ] 전투 화면의 논리 좌표계를 390×844 기준으로 정의하되 절대 좌표 UI는 사용하지 않음

### B1 — 전술판과 격자 렌더러

- [ ] 기본은 Hex Grid로 구현하고, `BattleMap`과 렌더러를 분리
- [ ] 화면 중앙에 지도 영역을 배치하고 상·하단 HUD가 지도 위를 침범하지 않도록 제약
- [ ] 지형 데이터에 movementCost, attackModifier, defenseModifier, fireModifier 반영
- [ ] 강·산·숲·평원·성 타일을 독립 에셋으로 제작
- [ ] 타일 경계선은 얇고 낮은 대비로 표시해 부대가 묻히지 않게 조정
- [ ] 카메라 확대·축소와 드래그는 후순위로 두고 첫 버전은 한 화면 전체 전장을 우선

### B2 — 부대 스프라이트 시스템

- [ ] 공격군·방어군 기본 보병 스프라이트 제작
- [ ] 기병·창병·궁병의 최소 3종 실루엣 제작
- [ ] 모든 스프라이트는 투명 배경 PNG 또는 Flame SpriteSheet로 관리
- [ ] 스프라이트 뒤에 흰색 사각 배경이 생기지 않는 asset QA 추가
- [ ] 부대 규모에 따라 작은 군단·중간 군단·대형 군단 시각 변형 제공
- [ ] 부대 하단에 병력 숫자 패널을 별도 레이어로 배치
- [ ] 장수 이름 깃발은 부대 스프라이트와 분리해 데이터로 렌더링

### B3 — 상단·하단 전투 HUD

- [ ] 공격군·방어군 이름과 총병력 표시
- [ ] 전투 일수, 군량, 사기, 보급 부족 상태 표시
- [ ] 공통 금속 프레임·패널 텍스처 적용
- [ ] 하단 명령 버튼을 한 손 조작 영역에 배치
- [ ] 버튼 상태를 enabled, disabled, selected, cooldown으로 구분
- [ ] 전황 정보 패널에 지형·날씨·현재 효과 표시
- [ ] 작은 iPhone과 Android 세로 비율에서 텍스트가 겹치지 않는지 확인

### B4 — 선택·이동·공격 피드백

- [ ] 부대 탭 선택 시 외곽선과 깃발 강조
- [ ] 이동 가능 칸은 청색 계열, 공격 가능 칸은 적색 계열로 표시
- [ ] 적 부대 탭 선택 시 대상 외곽선과 예상 피해 미리보기 표시
- [ ] 선택 상태는 Flutter/Flame 양쪽에서 단일 값으로 공유
- [ ] 부대가 겹치거나 빈 칸에 이동할 때 명확한 실패 피드백 표시
- [ ] 선택 해제와 뒤로 가기 동작을 정의

### B5 — 행동 연출: 12번 화면

- [ ] 일반 공격: 이동선·충돌 플래시·피해 숫자
- [ ] 화공: 화염 방향·타일 화재 상태·연기·주황 피해 숫자·사기 감소
- [ ] 돌격: 돌진 이동·강한 충돌·반격 손실
- [ ] 협공: 여러 아군 부대 연결선·협공 보정·동시 피해 표시
- [ ] 정보: 대상 정보 패널과 `informationRevealed` 상태 갱신
- [ ] 대기·퇴각: 짧은 상태 전환과 전투 로그 출력
- [ ] 애니메이션 중 추가 명령을 잠그고 완료 후 입력을 다시 허용
- [ ] 애니메이션은 로직 결과를 재생할 뿐 결과 자체를 결정하지 않음

### B6 — 전투 로그와 결과 연결

- [ ] `조조군 화공 실행` 같은 독자 문구로 행동 로그 생성
- [ ] 공격자·피격자·피해량·사기·화재 상태를 로그에 기록
- [ ] 화면 하단 로그는 최근 3~5건만 표시하고 전체 로그는 별도 조회
- [ ] BattleState.finished가 되면 13번 결과 화면으로 이동
- [ ] 포로가 있으면 14번 포로 처리 화면으로 이동
- [ ] 승리 시 점령지 귀속과 잔여 병력 주둔을 결과에 반영
- [ ] 패배·퇴각 시 출발지 귀환을 결과에 반영

### B7 — 에셋 제작·통합·성능

- [x] 전투 배경 지도: 성·부대·문자 없는 순수 지형 배경
- [ ] Hex Grid 오버레이: 투명 PNG 또는 Flame draw layer
- [ ] 부대 스프라이트: 진영별 색상 변형 3종 이상
- [ ] 장수 표식: 투명 깃발·이름 플레이트
- [ ] 화공·피해·충돌 파티클
- [ ] 전투 프레임·HUD 패널·버튼 상태 에셋
- [ ] 큰 배경은 Web·모바일별 해상도와 압축을 별도 관리
- [x] 동일 스프라이트를 캐시하고 매 프레임 새로 디코딩하지 않음
- [ ] 390×844 Web, iPhone 소형, Android 세로에서 60fps 목표

### B8 — 검증 및 출시 전 기준

- [ ] BattleEngine 순수 Dart 테스트: 모든 행동의 피해·사기·화재·보급
- [ ] Flame 렌더링 테스트: 선택·이동·공격 범위와 스프라이트 레이어
- [ ] 시드 기반 전투 재현 테스트
- [ ] AI 전투 결과가 플레이어 전투와 동일한 BattleEngine을 사용하는지 확인
- [ ] 전투 중 화면 회전·백그라운드 복귀 시 상태 보존
- [ ] 입력 연타·애니메이션 중 중복 명령 방지
- [ ] 11번 대기 화면과 12번 행동 연출 화면을 각각 실제 캡처해 비교
- [ ] 13번 결과와 14번 포로 처리까지 한 판의 전투 흐름으로 검증

## 우선순위와 범위 통제

### 반드시 먼저 구현

- 전술판·지형·부대 배치
- 상단 전투 HUD
- 하단 명령 바
- 선택·이동·공격
- 화공·피해 숫자·전투 로그
- 13·14번 결과 연결

### 이후 추가

- 날씨와 풍향
- 카메라 확대·축소
- 증원·매수·특수 계략
- 다양한 병종별 전용 애니메이션
- 네트워크 리플레이

초기 목표는 대규모 실시간 전투가 아니라, 한 화면에서 부대 위치와 판단 결과가 명확히 보이고 한 번의 행동이 시각적으로 납득되는 전술 전투다.

- [ ] Web build 및 모바일 세로 QA 통과
