# 참고 화면 대비 이미지 에셋 갭 분석

작성일: 2026-08-21

## 1. 목적

첨부된 세로형 고전 군주제 전략게임 화면을 시각적 기준으로 삼아, 현재 프로토타입에 부족한 이미지 에셋을 목록화한다.

이 문서에서 말하는 “유사”는 원작의 그래픽·초상화·맵·폰트·문구를 복제한다는 뜻이 아니다. 정보 밀도, 화면 역할, 어두운 목재 패널, 청동 테두리, 지도·장수·명령 중심의 시각 언어를 독자적인 가상 세계관으로 재구성한다는 뜻이다.

## 2. 현재 프로젝트에 이미 있는 에셋

| 에셋 | 사용처 | 현재 한계 |
|---|---|---|
| `title_background.png` | 시작 화면 | 제목 로고, 메뉴 프레임, 장식 문양은 코드 위젯 |
| `world_map_background.png` | 시나리오·군주 선택·세계 지도 | 실제 지역 마커·세력 깃발·도시 라벨·안개는 코드/텍스트 |
| `battle_background.png` | 플레이어 전투·AI 관전 | 지형 타일·부대 배치·전투 이펙트는 별도 필요 |
| `panel_texture.png` | 지역 정보·명령 패널 | 9-slice 프레임, 상태별 버튼, 탭 장식이 없음 |
| `command_icon_strip.png` | 명령 패널 상단 장식 | 개별 아이콘 파일이 아니어서 버튼별 의미 전달이 약함 |
| `officer_portrait_warrior.png` | 장수 아바타 일부 | 20명 장수를 3장으로 반복 표현함 |
| `officer_portrait_strategist.png` | 장수 아바타 일부 | 인물별 고유성 없음 |
| `officer_portrait_governor.png` | 장수 아바타 일부 | 포로·군주·AI 장수 구분 프레임 없음 |

현재 코드에서 `Icons.*`, `CircleAvatar`, `Text`, `CustomPainter`로 대체된 시각 요소가 많다. 따라서 배경은 개선됐지만 참고 화면처럼 “모든 정보 블록이 하나의 완성된 게임 스킨에 속해 보이는 상태”는 아니다.

- P0: 화면의 정체성과 플레이 가능성을 좌우하며 먼저 생성해야 하는 에셋
- P1: 참고 화면과의 완성도 차이를 크게 줄이는 에셋

## 4. 공통 UI 에셋 요구사항

### 4.1 패널과 버튼

현재 `panel_texture.png` 하나를 여러 영역에서 재사용하고 있다. 참고 화면 수준으로 보이려면 다음 상태를 각각 준비해야 한다.

- 창 프레임: 일반, 강조, 경고, 비활성
- 버튼: 일반, 눌림, 선택, 비활성
- 탭: 내정, 군사, 인사, 이동, 외교, 첩보
- 모달: 확인, 취소, 위험 행동
- 구분선: 금속선, 장식형 구분선, 섹션 제목판
- 9-slice 대응 PNG: 모바일 화면 폭이 달라도 모서리가 찌그러지지 않아야 함

권장 원본 규격:

- 패널 프레임: 360×220 또는 9-slice용 96×96 모서리 샘플
- 버튼 프레임: 320×72, 실제 표시 높이 40~48dp
- 탭 프레임: 96×64
- 아이콘: 64×64 또는 96×96 투명 PNG

### 4.2 자원과 상태 아이콘

텍스트만으로 표시되는 숫자는 참고 이미지보다 게임성이 약해 보인다. 다음 아이콘을 통일된 청동·청록 스타일로 제작한다.

- 금, 군량, 병력, 인구, 민심, 개발, 치수, 성벽
- WAR, INT, CHA, 충성도, 사기, 건강
- 성공, 실패, 경고, 정보 공개, 안개, 동맹, 적대
- 상승, 하락, 유지, 잠김, 선택됨, 실행 완료

### 4.3 장수 초상화 체계

현재 3개 초상화를 반복 사용하므로 군주 선택·지역 장수 목록·포로·외교·첩보가 모두 같은 인물처럼 보인다.

필요한 최소 세트:

- 핵심 군주 3명: 대형 512×640
- 주요 장수 12명: 256×320
- 일반 장수 8명: 192×240
- 포로/재야/사망/선택 프레임: 각 상태 1종 이상
- 군주·태수·장군·첩자 역할 배지

이미지는 모두 가상 인물이어야 하며, 데이터의 `officer.id`와 직접 매핑한다. 해시로 초상화를 임의 반복 배정하는 현재 방식은 최종 데이터팩에서 제거한다.

## 5. 전투 전용 에셋 요구사항

현재 전투는 배경과 부대 스프라이트까지 존재하지만, Flame 화면이 아직 다음 요소를 코드 도형으로 그린다.

- P0 지형 타일: 평원, 숲, 산, 강, 성채의 5종 타일 아틀라스
- P0 부대 변형: 공격군, 방어군, 선택됨, 사기 저하, 화재, 퇴각
- P0 장수 깃발: 세력 3종과 총대장 강조 1종
- P0 선택/범위: 이동 가능, 공격 가능, 협공 가능, 점유 불가
- P0 결과 이펙트: 화공, 돌격, 일반 공격, 피격, 사망, 퇴각
- P1 환경 연출: 연기, 불씨, 먼지, 강물 반짝임, 화면 흔들림용 오버레이

권장 방식:

```text
BattleState
  ↓
BattleEvent
  ↓
Flame Component / SpriteAnimation
```

이미지 에셋은 계산 로직에 직접 들어가지 않고 `BattleEvent`를 받아 재생한다. 스프라이트는 정사각형 128×128 또는 256×256, 애니메이션은 프레임당 동일 크기로 만든다.

## 6. 생성 우선순위

### Batch A — P0 화면 정체성

1. 패널·버튼·탭 프레임 전체 상태
2. 자원·능력치·행동 아이콘
3. 군주 3명과 주요 장수 12명 초상화
4. 세력 문장 3종과 세계 지도 도시 마커
5. 시나리오 썸네일 4종
6. 전투 지형 타일 5종과 부대 상태 스프라이트
7. 승리·패배·월말 이벤트 플레이트

### Batch B — P1 플레이 피드백

1. 탐색 장면과 발견 결과
2. 등용 성공·거절·관계 아이콘
3. 병력 이동·보급·출병 준비 아이콘
4. 포로 처리·외교·첩보 전용 아이콘
5. 화공·돌격·피격 이펙트

### Batch C — P2 완성도

1. 역할별 초상화 프레임과 상태 배지
2. 장식용 두루마리·봉인·책·깃발
3. 전환 화면과 로딩 일러스트
4. 월말 이벤트별 변형 배경
5. 세력별 색상 변형과 계절 변형

## 7. 생성 프롬프트 표준

모든 생성 요청은 다음 기준을 공유한다.

- Use case: `ui-mockup`, `stylized-concept`, `historical-scene` 중 하나
- 독자적인 가상 세계와 인물
- 1990년대 전략게임의 정보 밀도와 회화적 질감만 참고
- 읽을 수 있는 텍스트·로고·워터마크 생성 금지
- 투명 배경이 필요한 스프라이트는 실제 alpha 채널 요구
- 초상화는 머리·어깨 중심, 동일한 조명과 배경 질감
- 아이콘은 서로 분리된 단일 오브젝트, 작은 화면에서도 식별 가능
- 프레임은 9-slice를 고려해 모서리와 중앙 영역을 분리
- 생성 후 `view_image`로 투명도·잘림·문자 발생 여부를 검사

## 8. 파일명·데이터 연결 규칙

```text
assets/images/ui/panel_window_normal.png
assets/images/ui/button_primary_pressed.png
assets/images/icons/resource_gold.png
assets/images/icons/command_develop.png
assets/images/portraits/officer_001.png
assets/images/portraits/officer_002.png
assets/images/map/province_marker_player.png
assets/images/map/province_marker_enemy.png
assets/images/battle/terrain_forest.png
assets/images/battle/effect_fire_01.png
```

데이터에는 직접 경로를 하드코딩하지 않고 다음처럼 asset key를 둔다.

```json
{
  "id": "officer_001",
  "portraitAsset": "portraits/officer_001",
  "factionEmblemAsset": "emblems/force_red"
}
```

`AssetRepository`가 플랫폼별 확장자와 해상도 변형을 해결한다. Web·iOS·Android가 같은 key를 사용해야 한다.

## 9. 완료 기준

- [ ] 참고 이미지 17개 화면 각각에 전용 이미지 또는 독자적인 장식 에셋이 있다.
- [ ] 아이콘 대신 임시 `Icons.*`를 사용하는 P0 UI가 없다.
- [ ] 장수마다 고유 `portraitAsset`이 연결된다.
- [ ] 지역마다 도시 마커와 세력 문장이 데이터로 연결된다.
- [ ] 버튼·패널이 일반/선택/비활성 상태를 구분한다.
- [ ] 전투 지형·부대·이펙트가 코드 도형만으로 표현되지 않는다.
- [ ] 390×844 기준 화면에서 텍스트·이미지·버튼이 겹치지 않는다.
- [ ] Web build와 iOS/Android asset bundle 검증이 통과한다.
- [ ] 원작 그래픽·초상화·폰트·맵·문구를 사용하지 않는다.

## 10. 결론

현재 에셋은 “배경과 일부 장식이 있는 기술 프로토타입” 단계다. 참고 이미지와 비슷한 완성도를 내려면 단순히 배경을 더 생성하는 것보다, 화면별 상태 에셋과 장수·지역·전투 데이터의 고유 매핑을 먼저 완성해야 한다.

다음 구현 순서는 `Batch A → ImageAssetRepository → 화면별 연결 → Batch B 이펙트 → 실제 모바일/Web 시각 검수`로 한다.
